# Штаб.Точка

Публичная оболочка мобильного центра управления (ЦУП) и MAX-приложение. Секреты, токены, пароли, тексты приватных чатов и внутренние данные здесь не хранятся.

## Как это работает

- Локальный коллектор штаба публикует безопасную проекцию состояния в `live/status.json` (ветка `telemetry`; ветка `main` остаётся запасным источником на время перехода).
- Сайт полностью статический: папка `public/`. Панель (`public/index.html`, `public/app.js`) и MAX-приложение (`max/`, собирается в `public/max`) читают `live/status.json` прямо из GitHub через `public/live.js` и собирают экранное состояние в браузере. Серверной части и Vercel нет.
- Режимы: `live` (данные свежие), `stale` (проекция старше TTL плюс 5 минут кэша GitHub, показываем последние реальные данные с пометкой), `offline` (источник недоступен, нейтральный экран без старых ошибок).
- Ограничение: raw.githubusercontent.com кэширует файл до 5 минут, поэтому панель может отставать от коллектора на несколько минут. Возраст данных всегда показан в строке «Обновление данных».

## Что умеет

- Блок «Нужно внимание» первым: только реальные проблемы по картам и процессам, без ложных тревог.
- Карточка «Росток · публикации»: сегодня из лимита, очередь, следующий слот, всего опубликовано.
- Список автоматических процессов (n8n) с состоянием каждого.
- Кнопка «Обновить», авто-обновление каждые 30 секунд, при возврате на экран и при появлении сети.
- Кэш последнего состояния в браузере: при потере связи показываем последние данные с пометкой и временем.
- MAX-приложение (рабочий ЦУП, пять вкладок):
  - «Сегодня» — ближайшее событие, до трёх главных действий, дальше по дню, сигналы внимания, состояние источников. Диагностика не на первом месте.
  - «Календарь» — неделя, выбранный день, крупный список. Типы: встреча, выезд, ВКС, оплата, контрольная точка, автоматическое. Окончание показывается только подтверждённым, иначе «Окончание не указано». «Свободно» не пишем, пока источник не подтвердил.
  - «Проекты» — Список / Доска / Приоритеты над одним набором задач. Статус берётся из реестра Штаба как есть (OPEN, PROPOSED, IN_PROGRESS, WAITING, HOLD, DEFERRED, DONE…) и только группируется в колонки «К делу / В работе / Ожидаю / Готово». Приоритет (Сделать / Запланировать / Делегировать / Отложить) — отдельное измерение. Правки сохраняются на устройстве с пометкой «в реестр не записано». Перетаскивание — только мышью, на телефоне карточка → выбор.
  - «Системы» — живая схема Штаба (MAX/Telegram → Штаб → календарь, проекты, документы, ИИ-исполнители, автоматика → Росток → генерация → публикации). Цвет узла — только из источника, серый — не подтверждено. Импульс идёт лишь по работающим участкам свежего снимка. Нажатие на узел открывает нижнюю карточку с переходом в раздел.
  - «Входящие» — неразобранные карточки (прочитано ботом ≠ разобрано) и состояние получателей.
- Модель данных: `public/model.js` (PROJECT, TASK, EVENT, DOCUMENT, INBOX_ITEM, SYSTEM_NODE; состояния источника LIVE / STALE / OFFLINE / SYNCING / ERROR / NOT_CONNECTED). Тесты: `tests/model.test.mjs`.
- Защищённый слой: события, задачи и входящие приватны и в `live/status.json` не публикуются (smoke проверяет это). Канал для них пока не подключён — экраны честно показывают «не подключён». Ожидаемый формат снимка: `{schema:'private-1', generated_at, ttl_seconds, events[], tasks[], inbox[]}`, см. `fromPrivateSnapshot`.
- MAX-приложение: тема из мессенджера (светлая и тёмная), нативная кнопка «Назад» в проектах, тактильный отклик, запоминание вкладки, две колонки на планшете и десктопе.
- Панель ставится на экран «Домой» как приложение (manifest и иконки).

## Публикация

- Хостинг: GitHub Pages, деплой через `.github/workflows/deploy-pages.yml` при каждом коммите в `main`, кроме телеметрических (`live/status.json`).
- Адрес по умолчанию: `https://daridarom.github.io/shtab-tochka/`, MAX-приложение: `https://daridarom.github.io/shtab-tochka/max/`.
- В настройках репозитория Settings → Pages источник должен быть «GitHub Actions» (workflow включает Pages сам при первом запуске, если у него хватает прав).
- После деплоя запускается `production-smoke.yml`. Для своего домена задай переменную репозитория `SITE_URL`.

## Локальная проверка

```bash
cd max && npm ci && npm run build   # соберёт public/max
python3 -m http.server 8080 -d public  # панель на http://localhost:8080/
```

## Защищённый слой

Приватные события, задачи и входящие — через Yandex Cloud, см. `docs/private-layer.md`.

## Проверка веток

`.github/workflows/ci.yml` на каждой ветке кроме main: тесты модели и сборка MAX без публикации.

## Коллектор

Коллектору достаточно коммитить `live/status.json` в ветку `telemetry`. Проверка `/api/health` больше не нужна: сайт читает ветку `telemetry` первой и сам переходит на `main`, если ветки нет.
